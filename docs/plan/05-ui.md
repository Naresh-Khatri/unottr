# Phase 05 — UI

**Goal:** the three screens that make the archive usable. By this point everything already
works headlessly; this phase adds no pipeline logic.

**Depends on:** phase 04.

---

## Deliverables

- IPC surface: Tauri commands + a progress event stream.
- Recordings list with live job status.
- Transcript view: video player, speaker-labelled segments, click-to-seek, inline rename.
- Full-text search across every transcript.

## Tasks

### 1. IPC surface

Commands:

```
list_recordings(filter, sort) -> [RecordingSummary]
get_recording(id)             -> Recording + [Segment] + [Speaker]
search(query, limit)          -> [SearchHit]   # recording, segment, ts, snippet
rename_speaker(speaker_id, name)
retry_job(recording_id)
add_watch_folder(path) / remove_watch_folder(id) / list_watch_folders()
start_backfill(folder_id)
```

Events (Rust -> UI, no polling):

```
job_progress { recording_id, stage, pct }
job_done     { recording_id }
job_failed   { recording_id, error }
recording_discovered { recording_id }
```

### 2. Video playback — configure this first

Tauri v2 blocks arbitrary filesystem reads from the webview. Playing a user's recording
requires the **asset protocol** enabled with a scope covering their watch folders, and
`convertFileSrc()` on the path.

Do this before building the transcript view; it is the one thing in this phase that can be
architecturally annoying, and the scope must be **dynamic** — watch folders are added at
runtime, so a static allowlist in `tauri.conf.json` will not do.

### 3. Recordings list

- Rows: filename, recorded date, duration, status chip, speaker count.
- Active jobs show a live progress bar fed by `job_progress`.
- `Failed` rows show the error inline with a **Retry** button (decision #19: no modals, no
  notifications — the app must never interrupt a meeting in progress).
- `available = 0` rows are visibly marked but still open and still searchable.
- Virtualize the list; an archive grows without bound.
- Empty state points at "add a watch folder".

### 4. Transcript view

- `<video>` on the original file via `convertFileSrc`, plus a segment list beside it.
- Segments grouped into speaker blocks, each with a timestamp.
- **Click a segment -> seek the video.** `timeupdate` highlights the active segment and
  keeps it scrolled into view, with auto-scroll suspended while the user scrolls manually.
- **Rename a speaker inline**: editing `Speaker 2` -> `Priya` updates every segment of that
  speaker in this recording (decision #4). Per-recording only; no cross-meeting propagation.
- Find-in-transcript with match highlighting and next/prev.
- `available = 0`: player replaced by a "recording unavailable" notice; text fully usable.

### 5. Search

FTS5 across `segments_fts`, using `snippet()` for highlighted context. A hit shows the
recording, the timestamp, and the snippet; selecting it opens the transcript **seeked to
that moment**. This is the feature that makes an archive worth keeping — treat it as a
first-class screen, not a filter box.

## Acceptance criteria

- [ ] Video plays from an arbitrary user path, including a folder added after launch.
- [ ] Click-to-seek is accurate; the active segment highlight tracks playback.
- [ ] Renaming a speaker updates every one of their segments and survives a restart.
- [ ] Search finds a phrase from a real corpus transcript and jumps to the right timestamp.
- [ ] A job running in the background updates its row live, with no polling.
- [ ] A failed job shows its error and retries successfully from the button.
- [ ] `available = 0` recording opens, searches, and does not offer a broken player.
- [ ] `tsc --noEmit` and lint clean.

## Risks

- The asset-protocol scope is the classic Tauri v2 stumbling block. Solve it on day one of
  this phase.
- Long meetings produce thousands of segments — virtualize the transcript list too, not
  just the recordings list.

## Out of scope

Settings, tray, export, first-run. All of that is phase 06.
